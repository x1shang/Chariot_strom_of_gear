# v3.2：N20使能改到GPIO21

> 当前：GPIO21控制STBY；引起使能被拉低的c23-d26下拉支路已移除，STBY可正常拉高。但N20在150ms及300ms/30%试验中仍无动作，待看TB3当前接线。飞轮启停已由用户确认通过。

当前目标：保留已通过的方向键/转向和R2飞轮，绕开GPIO22使能回读异常。仅修改N20使能脚，R1仍是停车后点按150ms/30%。

## 唯一改线

1. 全部电机动力关闭，ESP32仅由USB供电，外部5V正极保持隔离。
2. 原来从ESP32 GPIO22通往a23的那根线，从GPIO22拔下；GPIO22此后不用。
3. 空载GPIO21经新程序验证能拉高后，断开USB，把这根线的ESP32端改插GPIO21。另一端仍在a23。
4. b23到TB3 STBY不动。后续诊断确认c23-d26下拉支路接入时使能被拉低，已将这只器件取下收好，暂不恢复；不是移除飞轮EN的那只下拉。GPIO25/26、TB3 VCC/PWMA及所有电机线不动。
5. 先仅恢复USB，核对接入TB3后的使能回读；之后才单独恢复N20动力，点R1测试。底盘、飞轮动力暂断。

程序中FEED_STBY=21；开启N20后若GPIO21不能读到高，会报FAULT feed enable并撤销全部电机输出。GPIO21回读是MCU端电平，不能代替TB3端子电压/电流测量。

## 已有证据

- v3.1：四轮架空测试，用户确认四轮均响应、松手停止。
- v3.1：仅接飞轮动力，按住R2约2秒后松开，用户确认“两台都转，松开后逐渐停下”。没有完成相向送球方向、带球发射或电流温升验收。
- v3.1：N20动力接通时R1未动；串口收到0800并出现feed=1，但TB3回读为0；全动力关闭、GPIO22外接线拔下后，R1期间仍回读0。只能说明GPIO22回读异常，尚未证明芯片损坏或定位外部故障。
- v3.2：691项主机检查通过，新增使能回读失败时停机回归。实际编译、烧录及USB启动通过。GPIO21空载可拉高；接入STBY下拉支路时触发feed_enable；移除该支路后使能恢复。N20仍不动，详细结果见[当前记录](logs/2026-10-18-stby21/README.md)。
