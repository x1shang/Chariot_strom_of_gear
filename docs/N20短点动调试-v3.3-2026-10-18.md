# N20启动占空比排查 v3.3

接线沿用v3.2：STBY用GPIO21，AIN1/2为25/26，GPIO22断开；导致使能被拉低的c23-d26下拉器件暂已取下。用户确认已对调两台130各自的两根输出线，飞轮方向现已正常。

N20在6V显示值、30%指令下，150ms和300ms均未转动。STBY已恢复，尚未排除启动占空比不足，也没有证明VM端实际电压或模块输出正常。用户本轮已确认N20与滑轨脱开，可以空载转动。

v3.3新增 `JOG 方向 毫秒 占空比百分数`：例如 `JOG 1 150 50`。第三参数可省略，省略时仍采用R1的默认30%。每次最多500ms，保留手柄中立/停车门槛、冷却、失联停机和使能回读保护。第三参数只影响该次点动，不更改R1配置。

STATUS动作期间显示实际N20ms、N20pct，N20pwm显示AIN1/2的LEDC回读。主机脚本host/jog_integrated_n20.py只发一次点动，验证固件到时撤销输出，最终再STOP；该脚本会产生动作，必须按实际电源和空载状态填写参数。

已完成编译及COM4烧录，上传校验通过。全部电机动力关闭时，`JOG 1 150 50` 验证通过：动作期间TB3=1、N20pct=50、N20pwm=128,0；在主机发送STOP之前，固件已自动恢复feed=0、TB3=0、N20pwm=0,0，未报故障。

门槛扫描记录见[本记录](logs/2026-10-18-n20-jog-100/README.md)。前两轮因未接动力而作废；此前的 30%/50%/70% 三轮也没有独立的供电证据，但因为真正带电的 50% 已确认不动，方向结论不受影响。

R1默认仍为30%/150ms。上述LEDC回读和ESP32的STBY引脚读取不证明TB3端实际电压、输出或电机电流正常；物理响应单独记录，不能用PWM回读代替。

**当前结论：N20 不是硬件死故障，故障定性改为「启动占空比不足」。** 带电实测门槛约在 **65%~75%**（150ms、空载、6V 显示值）：50% 完全不动、65% 临界抖动、75% 与 100% 正常起转，TB3 A 通道、STBY 使能、PWM 与电机本体均可用。因此 **`FEED_PERCENT=30` 的 R1 对接参数在实物上不会产生任何动作，必须上调**（建议 75%，必要时把 `FEED_PULSE_MS` 提到 200~250ms），改后需重编译烧录并用 R1 实按复验。仍未验证：TB3 VM 端实际电压与电机电流（6V 仅为降压板显示值）、带负载（弹匣/滑轨啮合）时的起转能力、反向启动门槛、以及门槛随电池电压下降的漂移。**整车验收仍不通过。** 飞轮方向已经用户确认正常，保留当前两台130输出接法。
