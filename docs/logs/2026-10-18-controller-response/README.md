# v3.1遥控响应、故障复现与修复

日期：2026-10-18；串口COM4，ESP32-D0WD-V3 rev3.1。当前版本为ChariotIntegrated-v3.1-R1，GPIO与R1/R2操作分配不变。主机自动诊断只发STATUS、结束时STOP；动作输入由用户手动操作遥控器。

## 已定位的故障

用户确认底盘动力接通、四轮架空后，首次读取到ps=1、mode=73，但hw=0，底盘输出全为0。随后用户再次明确确认所有电机动力断开、ESP32仅接USB。

在USB-only条件下复位、采样并让用户按上方向键，得到buttons=0010，紧接着出现`FAULT drive frequency; motor enables OFF; reset required`。因此接收器/按键数据已经到达，程序因频率检查而锁定；此时没有底盘输出。证据见before-fix/及reset-diagnosis/。

v3.0在写入PWM后使用ledcReadFreq作运行期检查。本机Arduino-ESP32 3.3.12的该API依赖占空比回读，不能作为与占空比无关的定时器状态查询。v3.1按已核对的本机核心元数据读取实际通道组、动态分配的timer，再调用ESP-IDF ledc_get_freq；零占空比也能查频率，避免使用假定的channel/2定时器映射。错误频率、写入失败、无效/超时手柄仍保持停机保护。STATUS增加持久fault及pwmhz。

## 编译与烧录

- 681项主机检查通过，包含占空比相关频率API返回0时的驾驶回归、真实定时器模型、故障频率停机、R1单脉冲、R2、失联/急停、转向与模式切换。
- Arduino-ESP32 3.3.12、esp32:esp32:esp32编译通过：程序289531字节，全局变量22576字节。
- 用户确认全部动力断开、ESP32仅接USB后，在COM4烧录v3.1并完成写入校验。没有通过主机发送FLY、JOG或其他运动命令。
- USB静止检查通过：hw=1、ps=1、mode=73、analog=1，观察到ready=1；fault=none，pwmhz=20000,5000,20000，所有电机指令为0。

## 操作响应与现场观察

- 断开底盘动力的45秒手动输入检查：406帧STATUS，27帧手柄输入、26帧非零底盘输出；四方向键均被记录，右摇杆转向范围-255至255；没有FAULT，结束STOP后输出为0。见after-fix-signal/。
- 用户确认底盘动力接通、四轮架空后完成60秒采样：541帧STATUS，94帧手柄输入、61帧非零底盘输出；无FAULT，定时器频率保持20000/5000/20000Hz。该次记录含下/左/右和右摇杆正向转向，未覆盖带动力上方向键及负向转向全部工况；之前断动力采样覆盖四方向和左右转向。见powered-wheels/。
- 本轮也记录到R2及L2按键；130和N20动力按用户确认继续断开，飞轮duty变化仅代表程序指令，不能算飞轮转动验证。
- 用户现场明确反馈：**“四轮都有响应，松开后停止”**，见physical-observation.json。这是四轮架空响应观察，不是落地负载、方向准确性或长期运行验收。
- 最后由主机发送STOP，回读chassis/fly/feed/TB3及四轮drive均为0；主机没有发运动命令。
- 130改线后的相向旋转、N20方向/行程、供电电压/电流/温升仍待单独验证；没有舵机。

接收到按键、程序输出指令、用户看到的轮子转动分别记载；遥测不能替代物理观察。
