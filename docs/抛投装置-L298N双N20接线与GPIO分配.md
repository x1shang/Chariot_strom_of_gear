# 抛投装置：L298N + 两台 N20 电机接线与 GPIO 分配

日期：2026-10-14。状态：已按用户要求恢复原`MecanumPS2Dpad`底盘遥控驱动，启动时手柄在线、ready=1、四轮输出为0；两台N20保持禁用。刚才的信号诊断与N20测试代码和日志完整保留。[恢复记录](logs/2026-10-14-restore-dpad/README.md) · [测试程序索引](测试程序索引-2026-10-14.md)。

用户报告 DRV8313 已烧坏，决定移除原 DRV8313、2804 无刷电机和 AS5600 磁编码器方案，改用一块 L298N 驱动两台 N20 有刷直流电机。用户选择 12V 动力方案；两台电机的具体型号、12V 额定连续运行依据及堵转电流尚未记录。本文按不带编码器的两线 N20 接法分配；若实物另有编码器线，需另行分配输入。

已确定机械职责：**2号电机连接转轴，拉绳蓄力；1号电机控制2号电机的位置以实现释放**。N20-A/OUT1/OUT2 对应1号，N20-B/OUT3/OUT4 对应2号。2026-10-14 新增并执行一次2号3秒、随后1号0.5秒的顺序测试；2号顺时针已确认，用户已确认1号试验极性为逆时针。

## 1. 拆除旧方案后释放的 GPIO

此处的“解码器”按原接线中的 **AS5600 磁编码器**理解，PS2 接收器保留。

| 移除的设备 | 原信号 | 释放的 ESP32 GPIO |
|---|---|---|
| DRV8313 | IN1 | 25 |
| DRV8313 | IN2 | 26 |
| DRV8313 | IN3 | 27 |
| DRV8313 | EN / nSLEEP | 14 |
| AS5600 | SDA | 21 |
| AS5600 | SCL | 22 |

共释放 **6 个可输出 GPIO：14、21、22、25、26、27**。DRV8313 的 FLT 原来未接，不增加可用 GPIO；移除电源线与 GND 也不计作释放 GPIO。

GPIO21 以前记录过 SDA 接线/上拉路径间歇异常，并未证明 ESP32 的 GPIO21 本身损坏。移除编码器的信号线及专用上拉、检查旧跳线和接头；动力关闭时验证 GPIO21 的高低电平后再用作方向信号。GPIO21/22 此后用于电机方向，不能同时连接 AS5600 或启用同脚 I2C。

## 2. L298N 信号分配

按经典 ESP32-WROOM-32E / ESP32-D0WD-V3 的现有接线分配。表中数字是 GPIO 丝印编号，不是排针位置，也不是 L298N 芯片封装脚号。

| L298N 模块端子 | ESP32 GPIO | 用途 | 接线要求 |
|---|---:|---|---|
| ENA | **14** | N20-A 独立 PWM 调速/使能 | 取下 ENA 常高跳帽；ENA 经独立 10kΩ 下拉到 GND |
| IN1 | **25** | N20-A 方向信号 1 | 直接接 3.3V GPIO 信号 |
| IN2 | **26** | N20-A 方向信号 2 | 直接接 3.3V GPIO 信号 |
| ENB | **27** | N20-B 独立 PWM 调速/使能 | 取下 ENB 常高跳帽；ENB 经独立 10kΩ 下拉到 GND |
| IN3 | **21** | N20-B 方向信号 1 | 检查原 SDA 接线故障；不再连接 I2C |
| IN4 | **22** | N20-B 方向信号 2 | 不再连接 I2C |
| OUT1 / OUT2 | 不接 GPIO | 接 N20-A 两根电机线 | 一路桥只接一台电机；输出不接系统 GND |
| OUT3 / OUT4 | 不接 GPIO | 接 N20-B 两根电机线 | 同上 |

建议代码常量（仅供后续固件使用）：

```cpp
constexpr uint8_t N20_A_EN = 14, N20_A_IN1 = 25, N20_A_IN2 = 26;
constexpr uint8_t N20_B_EN = 27, N20_B_IN1 = 21, N20_B_IN2 = 22;
```

ST 数据手册规定 L298 的方向及使能输入高电平门限为 2.3V，芯片逻辑电源典型为 5V。因此 ESP32 的 3.3V 控制信号可驱动其标准输入，**L298N 逻辑供电仍需 5V，不能用 ESP32 3V3 代替**。商品模块如另有输入电路，以实际模块说明为准。[ST L298 数据手册，表 4](https://www.st.com/resource/en/datasheet/l298.pdf)

## 3. 全车 GPIO 冲突核对

| 子系统 | GPIO / 固定接法 |
|---|---|
| 底盘左前 FL | 16 / 17 |
| 底盘左后 RL | 18 / 19 |
| 底盘右前 FR | 23 / 32 |
| 底盘右后 RR | 15 / 5 |
| 两块 TB6612 共用 STBY | 33，保留 10kΩ 下拉 |
| PS2 CLK / CS / CMD / DAT | 2 / 4 / 12 / 13 |
| 新抛投 N20-A：ENA / IN1 / IN2 | 14 / 25 / 26 |
| 新抛投 N20-B：ENB / IN3 / IN4 | 27 / 21 / 22 |

共 19 个互不重复的 GPIO：底盘 9 个、PS2 4 个、新抛投 6 个。新分配全部取自已释放的 GPIO，不挪动底盘和手柄接线。旧两线法文档中 AS5600/DRV8313 保留引脚、无舵机余量等结论属旧方案；当前六个释放引脚已全部分配给 L298N，仍未额外预留输出脚。

## 4. 12V 动力与 5V 逻辑供电

| L298N 电源端子 | 接法 |
|---|---|
| VS / 模块标注的 +12V | 合适的 12V 动力源 → 保险丝 / 物理断电开关 → L298N 动力正极 |
| GND | 直接回公共地端子，与 ESP32 GND、逻辑 5V 负极及底盘共地 |
| 5V / VSS | 确认模块允许外部逻辑供电后，用独立稳定 5V 供电；先按模块说明禁用板载 5V 稳压器 |

模块的 **5V-EN / 板载稳压跳帽**与 **ENA、ENB 通道跳帽**用途不同。外接逻辑 5V 前，确认稳压器已按该模块要求隔离，不能把板载 5V 输出和外部 5V 电源并联；具体跳帽状态依据实物电路，不仅凭“L298N”名称判断。不要由 L298N 的 5V 端给 ESP32 回供电，USB 调试仍按现有规则隔离降压到 ESP32 的正极线。

底盘 TT 电机已确认额定 3–6V，早期记录曾将 VM 降到 3V，2026-10-07 复测则使用过 6V；现车 VM 必须以实测为准，不能把早期 3V 写成当前已确认值。**底盘保留与其电机匹配的独立动力分支，只有 N20 的新分支选用 12V**。如果现有 VADJ 正给底盘供电，不能直接把它调到 12V；应从适配的 12V 源另分支，或为底盘另设符合 TT 额定电压的降压分支。电机动力线与回流直接走合适线径的电源线及端子，不走面包板或细杜邦线。

L298 是双极型桥，电机端电压会低于动力输入电压；其总导通压降随电流变化，1A 时数据手册给出典型约 1.8V。12V 输入不代表电机端恒定 12V。芯片每路 2A 的直流绝对最大额定值不能当作商品模块可长期承受的电流，需结合 N20 的堵转电流、两路总负载和散热确认。[ST L298 数据手册，表 1、表 4](https://www.st.com/resource/en/datasheet/l298.pdf)

## 5. 控制与迁移要求

| 单路动作 | ENA / ENB | 该路两个 IN 信号 |
|---|---|---|
| 禁用 / 滑行停止 | 0 | 任意；初始化时均设 0 |
| 正向调速 | PWM | 1 / 0 |
| 反向调速 | PWM | 0 / 1 |
| 电气制动 | 1 | 两个 IN 相同；需先低速实测 |

上述是桥的电气方向，电机实际机械正向需逐台确认。使能为低是滑行停止，不能保证机构抱死。[ST L298 数据手册，表 5](https://www.st.com/resource/en/datasheet/l298.pdf)

1. 完全断电后拆除旧 DRV8313、AS5600 供电与信号连接；旧设备不能与新模块同时挂在这六根线上。保留 PS2 和底盘原有线束。
2. 取下 ENA/ENB 常高跳帽，各加 10kΩ 下拉；确认模块无其他硬拉高路径。新程序启动、复位、停止、手柄断联时应使两个 EN 为低。
3. 旧 `PS2Catapult` 和 `Stage1/Stage2` FOC 固件不能用于新模块：它们会对已重新分配的 GPIO 输出旧信号。不要沿用旧编译/烧录指令。
4. `MecanumPS2Dpad` 仅控制底盘，不含 N20 控制。2026-10-14 板上当前已恢复独立 `N20Motor2DirectionCheck`，只允许2号顺时针一次3秒，1号和底盘禁用。此前 `N20SequenceTest` 及记录保留，未来两台顺时针用DIR -1 1。未来整合时，底盘八路 PWM 与新增 ENA/ENB 两路 PWM 的通道和定时器应统一分配。
5. 先关闭动力，验共地、5V逻辑供电、GPIO21/22电平和 EN 默认低；之后用符合电机规格的限流动力源，逐台短时低占空比空载验方向与停止，再验双路运行。
6. 移除 AS5600 后不再有原来的角度反馈，旧 90° 定位/自动返回功能不再成立。两台 N20 的职责已确定；行程限位、原点检测、蓄力/释放完整动作与互锁仍需设计。

已执行2号单次方向测试；完整蓄力/释放流程未实现。回读互锁及本次跳帽异常处理见测试记录；不能在跳帽常高或停止回读不符合预期时执行运动。

## 6. 2026-10-14 实机试验结果（接线与供电部分）

用户在本日实机抛投试验后报告四项问题，完整记录与证据边界见[实机抛投失败记录](logs/2026-10-14-throw-test/README.md)。其中与本接线文档直接相关的两条：

- **供电：** 用户报告电池像是断路，整机只能直连电源。本文 §4 的 12V 动力分支与 5V 逻辑分支方案不变，但在用户测出电池端电压与通断、定位断点（电芯 / 保护板 / 接插件）之前，**不能把"电池坏了"写成结论**，也不能据此调整 12V 或 VM 标称值。此前记录过的 12V 锂电池组参数仅为商品页标称，未认证实物能力。
- **机械：** 3D 打印配合孔过大导致齿轮滑齿、限位器补救失败；卷线轴没有半月形杆，齿轮沿轴向滑动脱落且无法装回；人力满行程下抛射初始角度仍接近水平。这三条属机构与加工问题，不改变本文的 GPIO 分配，但说明**在机构重做前继续调试固件没有意义**。

该次机构失败报告没有新的接线改动、烧录或串口记录，当时板上为 `N20Motor2DirectionCheck` v2；后续顺序测试见下节。
