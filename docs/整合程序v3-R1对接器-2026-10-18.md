## 当前操作

| 操作 | 行为 |
|---|---|
| 松开所有按键，右摇杆回中，连续5帧 | 自动ready/armed，不需要START |
| 方向键 | 前后、横移、斜移，保留原轮向、100%目标、加速斜坡和300ms换向等待 |
| 右摇杆横轴 | 比例转向，可与方向键叠加；中位128、死区±20 |
| 按住R2 | 双130从0经1200ms爬升至100%，最多10秒；可与驾驶并行 |
| 松开R2 | 撤销飞轮输出，飞轮惯性滑行；若N20此次动作在飞轮运行时启动，也一并撤销 |
| 停车后点按R1 | N20按配置方向输出150ms、30%占空比，松开R1仍运行到时限；无需先按R2 |
| 一直按住R1 | 只触发一次，不连发；上次停止后至少800ms，再次松开并点按才接受 |
| 飞轮已运行时点R1 | 必须已预转2500ms；预转未完成或车辆在行驶时拒绝，不排队 |
| N20动作中出现驾驶输入 | 所有电机停止并锁定，须重新松键回中 |
| 圆圈或串口STOP | 全部电机撤销输出并锁定，重新松键回中后就绪 |
| 无效手柄帧、150ms无有效帧 | 全部电机撤销输出并锁定 |
| SELECT、L1、叉 | 本版不控制机构；GPIO27不输出舵机脉冲，SERVO ON也被拒绝 |

R1是定时动作，不是到位控制；150ms和30%是原配置的调试初值，不能保证滑轨完成对接。需现场确认方向和行程，调整RobotConfig.h的FEED_POLARITY、FEED_PULSE_MS、FEED_PERCENT，再编译烧录；手柄脉冲不得超过FEED_JOG_MAX_MS（当前500ms）。未实现到位传感器或卡滞检测。

## 与本次实际接线的对应

| 功能 | 接线 |
|---|---|
| 双飞轮使能 | GPIO14经第20排分到L298N ENA和ENB；两个EN跳帽取下 |
| 使能默认关闭 | 第20排b20经一只10kΩ到第26排e26；合并EN共用下拉即可 |
| 飞轮方向 | L298N IN1/IN3接ESP32同源3V3；IN2/IN4接GND |
| N20方向与使能 | GPIO25/26/22分别接TB3 AIN1/AIN2/STBY；STBY有另一只10kΩ下拉 |
| N20逻辑与输出 | TB3 VCC/PWMA=3V3；BIN1/BIN2/PWMB=GND；AO1/AO2接N20 |
| 地线 | 第26排左右侧各从ESP32 GND引入；TB3和L298N功率GND各自直接回降压板GND，不经面包板 |
| L298N逻辑电源 | 5V-EN取下，外部降压板5V-OUT接L298N 5V |
| 动力接线状态 | 用户报告TB3 VM已接VADJ-OUT、L298N动力正极已按原位置恢复；本次烧录时全部动力断开 |
| 舵机 | 未安装，GPIO27留空或仅保留a24引线；SERVO_INSTALLED=false |
| 保留脚 | GPIO21不用；底盘和PS2接法保持原样 |

电机线重新插接过，两台130是否相向送球、N20是否向对接方向运动均需重新点动核对。程序状态、PWM占空比和150ms到时均不代表实测电压、电流、转速、温升或机械到位。N20具体型号及VADJ实际电压仍未取得仪器/铭牌记录。

## 烧录和检查范围（以下v3.0初始化修复为历史记录）

本次先执行主机回归和Arduino-ESP32 3.3.12实际编译。烧录前后记录源码/二进制哈希；只在用户确认动力断开、ESP32仅接USB后操作COM4。启动检查脚本`host/verify_integrated_after_upload.py`只发送STOP与STATUS，不发送任何动作命令。

首次启动发现hw=0：原初始化代码在零占空比时检查ledcReadFreq，但本机3.3.12的esp32-hal-ledc.c第408–417行明确在占空比为0时返回频率0，导致误判。已保留失败日志，修正为初始化检查attach、写0成功与占空比回读0；只在用户请求非零输出时检查频率。主机stub也改为同样的零占空比返回行为，并覆盖运行期错误频率时停机的情况。初始化不为测频而产生非零脉冲。

实际结果见[本次记录](logs/2026-10-18-integrated-r1/README.md)。旧v1/v2日志和桌面ZIP保留其原版本含义，不能当本版烧录证据。
