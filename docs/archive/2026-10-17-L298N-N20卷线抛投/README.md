## 逐字节校验

文件清单、归档来源提交与 SHA-256 见 [manifest.json](manifest.json)。`manifest.json` 的 SHA-256 是对**归档当时工作区（或来源提交）的实际字节**计算的。`.gitattributes` 对 `docs/archive/**` 显式设为 `-text`（不做行尾转换），因此这些快照在索引、检出与工作区三处字节一致。

校验方法：对每个 `snapshot_path` 逐个算 SHA-256，与 `manifest.json` 的 `sha256` 比较。

## 旧方案为什么终止

用户报告的直接原因：**卷线/蓄力机构扭矩过大，电机被撕裂**。此前 2026-10-14 的实机试验还记录过四项失败（电池像是断路、3D 打印孔过大滑齿、卷线轴无半月形杆导致齿轮脱落、人力满行程下抛射角仍接近水平）。这些均为用户现场口述，**没有串口日志、仪器读数或照片**，不作为实测参数引用，详见[失败记录](../../logs/2026-10-17-卷线方案失败-电机撕裂/README.md)。

工程结论：把电机经齿轮与卷线轴硬联到拉绳与限位端时，机构会以堵转/冲击扭矩反作用于电机，力的上限由**机构与限位**决定，而不是由电机决定；这正是「电机被撕裂」的力学来源。摩擦飞轮方案把能量储存在飞轮转子动能里，负载是惯性负载，没有硬限位反冲，力矩受电机自身转矩—转速特性约束，从原理上避开了这一失效模式。
