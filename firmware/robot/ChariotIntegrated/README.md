## 手柄操作

| 操作 | 行为 |
|---|---|
| 上电后松开所有键，并让右摇杆回中 | 连续5帧有效中立后ready=1、armed=1，自动就绪；**不需要START/L1**，不会自动转飞轮或送球 |
| 方向键 | 前后/横移/斜移，保留100%目标占空比、原轮极性、加速斜坡和300ms换向等待 |
| 右摇杆横轴 | 比例转向，可与方向键叠加；中位128、死区±20；数字模式41忽略摇杆尾部字节 |
| 松开方向键并让右摇杆回中 | 撤销底盘输出 |
| **按住R2** | 双飞轮从0经1.2秒爬升到100%；可边驾驶边预转；松开R2撤销飞轮，以及在此次飞轮运行期间启动的N20动作 |
| **停车后点按R1** | N20朝当前待发方向输出一次 **1750ms / 80%** 脉冲，松开R1仍运行到时限；无需先按R2。**每成功点按一次方向翻转**，第三次回到第一个方向；被拒的点按（冷却/停车/预转/未使能）不消耗方向。上次停止后至少800ms再点按。飞轮若正在运行，须预转至少2.5秒；行驶、预转或冷却未完成时拒绝且不排队。待发方向见STATUS的N20next，上一次实际方向见N20last |
| R2连续按住达到10秒 | 自动撤销飞轮/N20输出，必须松R2再按才能重新启动；不同于远程旧接线程序的无时限恒高 |
| SELECT / L1 / 叉 | 本版不控制机构；舵机未安装，SERVO_INSTALLED=false，GPIO27保持低 |
| 圆圈CIRCLE / 串口STOP | 停全部电机并锁定，舵机冻结最后脉宽；松开所有键且右摇杆回中连续5帧后重新就绪 |

**方框不控制飞轮，START不切换发射解锁，叉不再启动N20，R1不再控制舵机。** GPIO不改变。N20动作中出现驾驶输入会停机锁定；一直按住R1不连发。R1点按是定时动作，当前没有到位传感器，不能保证滑轨完成对接。

启动请求模拟模式73/79；数字模式下只在静止且无按键时每2秒重试。STATUS显示RX、turn、analog；若一直为41，可尝试手柄ANALOG/MODE键。模式切换、急停及失联恢复均要求松键并回中，不能推着摇杆自动恢复运动。

pretime=1只是经过预转时间，不是转速确认；舵机us是脉宽，不是实测角度；1750ms脉冲不保证刚好一颗球或机构到位。无线接收器若重复旧有效帧，固件不能仅凭有效帧识别无线侧失联，需现场验证。

## 串口调试命令

串口115200，选“换行”。除STOP/STATUS外，动作命令要求有效手柄中立、`ready=1`、底盘停止；ARM保留兼容用途，中立就绪后不必先发ARM。不依赖主机定时发STOP，固件自己限时。

| 命令 | 含义 |
|---|---|
| `STATUS` | 查看版本、硬件初始化、PS2、中立、发射解锁及各路输出指令 |
| `ARM` | 可选兼容命令；中立就绪自动解锁，不产生运动 |
| `STOP` 或 `DISARM` | 撤销所有电机驱动，舵机冻结当前指令；重新松键中立后才接受解锁 |
| `FLY 30 3000` | 30%目标占空比，双飞轮总共3秒（包含软启动）；占空比1–100%，时长1–10000ms。测试期间任意手柄按键或右摇杆偏离死区会终止并锁定 |
| `JOG 1 100` / `JOG -1 100` | N20两方向分别点动100ms；默认80%，时长1–3000ms；飞轮必须停止。两次点动停止间隔至少800ms。JOG不改变R1的待发方向 |
| `JOG 1 150 50` | 仅这一次N20点动用50%占空比、150ms；第三参数范围1–100，不修改R1默认参数。保留停车、手柄中立、最大3000ms和800ms冷却门槛 |
| `SERVO ON` / `SERVO 1520` | 本版未安装舵机，命令被拒绝，不输出GPIO27脉冲 |
| `SERVO OFF` | 本版保持无舵机脉冲 |

上电先用`STATUS`确认：`hw=1`，未动作时`chassis=0 fly=0 duty=0 feed=0 TB3=0 servo=0`；PS2在线且全松键后`ready=1`。`hw=0`时禁止运行，查初始化或PWM错误并复位。

## 接线与资源

- GPIO14 → L298N ENA与ENB；EN跳帽取下；合并EN共用一只10kΩ下拉（原有两只也可保留）。IN1/IN3固定3V3，IN2/IN4固定GND。
- GPIO25/26/21 → TB3 AIN1/AIN2/STBY；PWMA=3V3，VCC=3V3，STBY原外加下拉支路导致无法拉高，目前诊断性移除，待换经确认的10kΩ并复测；AO1/AO2接N20。
- GPIO27当前无舵机，保持低；GPIO22异常，外部线拔下不用。
- 底盘0–7通道20kHz/8bit，飞轮CH8为5kHz/8bit，舵机CH9为50Hz/16bit，N20 CH10/11为20kHz/8bit。按本机Arduino-ESP32 3.3.12动态定时器规则分开配置，初始化返回值和频率均检查。
- 不混用自动抢占通道的Servo库；没有AS5600、FOC、编码器或到位传感器代码。

## 需要现场标定的配置

编辑同目录`RobotConfig.h`，再重新编译。已有初值为：飞轮100%、爬升1200ms、预转许可2500ms、单次最多10000ms；N20正向极性1、占空比80%、一次1750ms、交替方向、恢复间隔800ms、反向保护300ms、串口JOG上限3000ms；舵机中位1500µs、1400–1600µs范围。上述时间/脉宽均是初始调试值，不是物理验收数据。

先脱开N20机构用JOG辨方向，再设置`FEED_POLARITY`（1或−1）。逐步标定R1对应的`FEED_PULSE_MS`，不可超过`FEED_JOG_MAX_MS`；到位精度需求应加限位/编码器，不靠无限延长脉冲。GPIO27禁用，不安装舵机。

## 构建与测试

Arduino IDE打开同名`.ino`，同目录三个`.h`一起保留，选ESP32 Dev Module（本次3.3.12）。命令行可运行仓库`tools/build-integrated.ps1`，它把4个源码文件复制到英文临时目录编译，避免中文路径链接问题；**脚本只编译，没有烧录或串口命令**。用`-Cli`和`-DataDirectory`指定本机安装路径。桌面包保留同样目录结构。

主机侧测试入口`tests/run-integrated-tests.cmd`（本机MSVC BuildTools路径），使用模拟Arduino，不接串口，不驱动硬件。覆盖启动中立、底盘及转向、软启动/超时、R1独立定时脉冲/长按不重触发/冷却不排队、驾驶互锁、失联/停止、N20换向等待、无舵机脉冲、时间回绕及PWM失败。烧录后只发STOP/STATUS的检查入口为`host/verify_integrated_after_upload.py`。

v3.1不再通过占空比相关的ledcReadFreq判断定时器状态。按本机3.3.12的periman元数据取得LEDC通道组和实际动态分配的timer，再用ESP-IDF ledc_get_freq直接查询；初始化和运行期都能验证频率。启动另核对attach/写0/占空比回读，频率异常仍会撤销输出。STATUS增加fault和pwmhz，STOP不会清除已锁定的硬件故障；修复后需复位。

电流、电压、温升、实际转速、送球到位、平台扭矩和安全范围都需要现场检查。软件PWM不是电流保护，STOP也不保证飞轮立即停转；物理急停和平台机械支撑仍需保留。

当前现场结果：飞轮启停已获用户确认，用户对调两台130各自输出线后确认方向正常。N20问题已定性为**启动占空比不足**而非硬件故障：30%/50%起不动、65%只抖动、75%空载起转、**80%带负载可带动机构3秒**，因此R1默认由30%/150ms改为80%/1750ms。[门槛扫描](../../../docs/logs/2026-10-18-n20-jog-100/README.md) · [带载3秒](../../../docs/logs/2026-10-18-n20-loaded-3s/README.md) · [v3.4交替说明](../../../docs/logs/2026-10-18-r1-alternate/README.md)。真实R1按键的交替与时长尚待用户现场确认。

v3.4增加R1交替方向（`feedNextDirection`）与STATUS的N20next/N20last。交替只在被接受的按键上翻转；JOG不参与交替；待发方向跨STOP保留。

v3.3增加一次性JOG占空比参数及STATUS中的N20pwm（两根IN的PWM回读）。动作期间N20ms/N20pct显示该次实际指令；停止后显示R1默认配置。N20pwm是外设回读，仍不代表电机端电压或物理转动。
